## 修复过程与实现约束

1. 两个参考工程使用的旧 CodeMirror 依赖与 npm 当前解析出的 Obsidian 包不兼容。新工程固定 `obsidian` 为 1.14.4，并按它声明的 peerDependencies 对齐 CodeMirror state 6.7.6、view 6.43.13，随后安装与编译通过。
2. 表格使用固定布局，同时设置所有列宽和总宽度。仅设置单列宽度而保留自动表格总宽度，会使其他列被浏览器重新分配。
3. Live Preview 的原生表格 widget 带左右负边距和 padding。新样式去掉水平方向的扩展，保留原生纵向空间，滚动区域因此与正文对齐。
4. 观察器只监听子节点变化；装饰逻辑保持幂等，避免自己插入手柄后无限重复渲染。
5. 组件销毁、设置关闭与全局重置之前取消未完成拖动，避免清理 DOM 后又写回旧列组或旧列宽。
6. 编辑中的嵌套 CodeMirror 使用 `pre-wrap` 保留空白并换行，不把其编辑文本按普通 HTML 空白规则折叠。
7. Windows 下全量 `codegraph index` 受 MCP 已打开的数据库文件锁阻止；改用 `codegraph sync`，并通过 MCP 查询确认新代码已被索引。
8. Windows PowerShell 5.1 解析含中文的无 BOM 脚本时发生语法错误。`../scripts/package.ps1` 已使用带 BOM 的 UTF-8 编码保存；控制台编码仍显式设置 UTF-8，之后打包通过。

## 真实 Obsidian 验收范围

本轮尚未将插件安装到用户正在使用的 Obsidian 仓库。浏览器模拟与编译通过不能代表全部 Obsidian 主题、移动端和其他插件组合均已通过人工验收。

安装后建议使用 `./test-note.md` 完成以下检查：

1. 停用 Gridlock Tables 与 Table Style Tweaks，启用 Table Width Scroll。
2. 阅读视图和实时预览各拖动一次表头右侧，确认可缩窄、可拉宽，其他列保持原宽度。
3. 拉宽至超出正文，确认底部滚动条能到第一列和最后一列，正文边界不扩大。
4. 在实时预览中直接编辑单元格、添加或删除行，再切换阅读视图，确认原生编辑功能与列宽恢复正常。
5. 分栏打开同一笔记，在一侧调整，确认另一侧同步。
6. 改变窗口、分栏宽度和「缩减栏宽」设置，确认滚动区域跟随正文实际宽度。
7. 关闭再开启插件、重启 Obsidian，确认已保存的列宽恢复。
8. 按 Escape 取消拖动，再关闭插件，确认没有遗留手柄或列宽样式。

## 已知边界

- 源码模式显示 Markdown 文本；可拖动的表格对应实时预览与阅读视图。
- 本版验证普通顶层 Markdown 表格；嵌套引用、列表表格和自定义 HTML 合并单元格不在验证范围内。
- 修改源表头会改变表格标识。同一笔记内多个完全相同表头的表格，交换顺序后需重新调整列宽。
- 平台的滚动条自动隐藏设置可能影响滚动条可见性，横向滚动能力仍由容器提供。
